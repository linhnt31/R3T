## ✨ Key Features

- **Private blockchain-based Federated learning** with [Flower](https://flower.ai):
  + Easy to customize with different datasets, model architecture, aggregation algorithms, etc.
  + IDs, hash of local/global model updates and reward calculation is recorded on-chain via Ganache.
  + Scalable storage with **IPFS model storage** via Pinata.
  + **Blockchain/FL overhead metrics:** accuracy/loss, latency, throughput (TPS), and gas usage logged per transaction and aggregated per function call.

- **Static/Dynamic Critical Learning Period (CLP) detection:** based on gradient norm (FGN metric) [Optional].
- **Pure CLI operation:** no browser or FastAPI interaction required.

## ⚙️ Setup

### ⛓️ 1. Blockchain

**Step 1 — Start Ganache**

Using the desktop app:
```bash
./ganache-2.7.1-linux-x86_64.AppImage
```

Or using the CLI (recommended for headless/scripted runs):
```bash
ganache --deterministic --accounts 16 --defaultBalanceEther 5000
```

> The `--deterministic` flag ensures the same wallet addresses are generated every run, which is required because `blockchain_service.py` addresses clients by index (`accounts[client_id + 1]`).

**Step 2 — Compile and deploy contracts**

```bash
cd Blockchain
truffle compile
truffle migrate --network development
```

Check `truffle-config.js` to confirm the RPC host/port matches Ganache (default: `127.0.0.1:8545`).

---

### 📜 Smart Contracts

The project uses two Solidity contracts under `Blockchain/contracts/`:

- `Federation.sol`
  - Stores FL strategy metadata (`algoName`, `numRounds`, `numClients`) per session.
  - Stores local client update metadata per round via `addWeight(...)`.
  - Stores final global model metadata via `addModel(...)`.
  - Main read methods: `getWeight(...)`, `getModel(...)`, `getStrategy(...)`.

- `Contribution.sol`
  - Tracks per-client contribution records and cumulative balances.
  - Records contribution state via `calculateContribution(...)`.
  - Supports balance and contribution reads via `getContribution(...)`, `getBalance(...)`.

Important note:
- Only metadata is written on-chain (e.g., filepath/hash and contribution values).  
  Raw model weights stay off-chain and are referenced by hash.

---

### 📡 2. IPFS (Pinata)

The final global model is uploaded to IPFS after training. Add your Pinata credentials to `api_key.json`:

```json
{
  "api_key": "YOUR_PINATA_API_KEY",
  "secret_key": "YOUR_PINATA_SECRET_KEY"
}
```

After training, visit [https://app.pinata.cloud/pinmanager](https://app.pinata.cloud/pinmanager) to view or download the uploaded model.

## 🚀 Running the System

> **Note:** If you want standard blockchain-based federated learning (without CLP-aware client sampling), choose the `cfl` version (`--cfl`). This version is the most flexible baseline for customizing multiple scenarios (for example: different numbers of clients per round, datasets, alpha values, seeds, and round counts).

### 🖥️ Start the Server

```bash
cd Server
python server.py --num_rounds 100 --budget 1000
```

All options:

| Argument | Type | Default | Description |
|---|---|---|---|
| `--num_rounds` | int | required | Total FL training rounds |
| `--budget` | float | required | Total reward pool (ETH) |
| `--threshold` | float | `0.05` | Relative-change threshold for CLP detection |
| `--num_clients` | int | `25` | Total number of FL clients |
| `--min_available_clients` | int | *(= num_clients)* | Minimum connected clients before round 1 starts; defaults to `--num_clients` |
| `--seed` | int | `345` | Random seed for NumPy, TensorFlow, and output file names |
| `--dataset` | str | `cifar10` | Dataset name (`cifar10` or `fmnist`) |
| `--alpha` | float | `0.1` | Dirichlet alpha controlling non-IID strength (`> 0`) |
| `--clp` | int | `31` | First non-CLP round for client-sampling policy |
| `--batch_size` | int | `32` | Local training batch size sent to clients each round |
| `--local_epochs` | int | `2` | Local training epochs sent to clients each round |
| `--model_type` | str | `cnn` | Model architecture: `cnn` or `alexnet` |
| `--ratio` | float | `1.5` | Geometric growth ratio for per-client sample counts |
| `--cfl_clients_per_round` | int | `3` | Number of sampled clients per round when `--cfl` is used |
| `--is_resume` | flag | off | Resume training from the last saved session weights |
| `--clp_aware` | flag | off | CLP rounds: 1 pinned near-high-ID client (skip top 2, pick next 1) + 2 random; post-CLP: 3 random clients |
| `--cfl` | flag | off | Conventional FL sampling without CLP phase switching (3 random clients each round) *(default when neither flag is given)* |

`--clp_aware` and `--cfl` are mutually exclusive. If neither is passed, `cfl` is used.

Example with all options:
```bash
# cfl mode (default): 3 random clients every round (no CLP-dependent switching)
python server.py --num_rounds 81 --budget 5000 --threshold 0.05 \
    --num_clients 25 --seed 42 --dataset fmnist --alpha 0.1 \
    --clp 31 --batch_size 8 --local_epochs 2 --model_type cnn \
    --cfl --cfl_clients_per_round 5

# clp_aware mode: CLP rounds use 1 pinned near-high-ID + 2 random; post-CLP rounds use 3 random
python server.py --num_rounds 81 --budget 5000 --threshold 0.05 \
    --num_clients 25 --seed 42 --dataset fmnist --alpha 0.1 \
    --clp 31 --batch_size 8 --local_epochs 2 --model_type cnn --clp_aware
```

The server blocks until `--min_available_clients` clients have connected before starting round 1.

### 👥 Start Clients

#### Multiple clients from one terminal (recommended)

```bash
cd Client

# Launch clients 0 through 9
python launch_clients.py --num_clients 10

# Launch 20 clients
python launch_clients.py --num_clients 20

# Launch a specific subset
python launch_clients.py --client_ids 0 2 5 9
```

| Argument | Type | Default | Description |
|---|---|---|---|
| `--num_clients` | int | — | Launch clients 0 … N-1 (mutually exclusive with `--client_ids`) |
| `--client_ids` | int… | — | Launch specific client IDs |
| `--server_address` | str | `127.0.0.1:8080` | Flower server gRPC address |
| `--seed` | int | `345` | Random seed forwarded to every client process |
| `--dataset` | str | *(auto)* | Optional dataset override forwarded to every client process |
| `--alpha` | float | *(auto)* | Optional alpha override forwarded to every client process |
| `--model_type` | str | *(auto)* | Optional model override: `cnn` or `alexnet` |
| `--delay` | float | `2.0` | Seconds between launching each client process (avoids dataset-load collisions) |
| `--device` | str | `auto` | `auto`, `cpu`, or GPU index (`gpu:0`, `0`, etc.) |

If `--dataset`/`--alpha`/`--model_type` are omitted in `launch_clients.py`, clients read them from `Server/config_training.json`.

Each client's output is written inside the run folder under `client_logs/client_<id>_<timestamp>.log`.

```bash
tail -f ../report/temp/<run_folder>/client_logs/client_0_<timestamp>.log
```

Press **Ctrl+C** in the launcher terminal to gracefully stop all client processes.

### 🧬 Dataset and Model Selection

Model architecture and data pipeline are selected automatically from `--dataset` and `--model_type` (or from `config_training.json` when client-side args are omitted).

Supported datasets:

- `cifar10` (aliases: `cifar`)
- `fmnist` (aliases: `fashion_mnist`, `fashion-mnist`)

Input shape is selected automatically:

- CIFAR-10: `32×32×3`
- FMNIST: `28×28×1`

#### 🧠 CNN backbone (`--model_type cnn`, default)

```
Conv2D(32, 3×3, he_uniform) → BatchNorm → Dropout(0.3)
Conv2D(64, 3×3, he_uniform) → BatchNorm → MaxPool(2×2)
Conv2D(64, 3×3, he_uniform) → BatchNorm → MaxPool(4×4) → Dropout(0.2)
Flatten → Dense(256, he_uniform) → Dropout(0.1)
Dense(10, softmax)

Optimizer : Adam
Loss      : sparse_categorical_crossentropy
```

#### 🧠 AlexNet backbone (`--model_type alexnet`)

```
Conv2D(96, 3×3, same) → BatchNorm → MaxPool(2×2)
Conv2D(256, 3×3, same) → BatchNorm → MaxPool(2×2)
Conv2D(384, 3×3, same)
Conv2D(384, 3×3, same)
Conv2D(256, 3×3, same) → MaxPool(2×2)
Flatten → Dense(4096) → Dropout(0.5)
Dense(4096) → Dropout(0.5)
Dense(10, softmax)

Optimizer : Adam
Loss      : sparse_categorical_crossentropy
```

No comment/uncomment edits are required to switch datasets or model types.

To add or update datasets/models centrally, edit:

- `utils/model_dataset_registry.py`
  - `DATASET_ALIASES` / `DATASET_REGISTRY` for dataset names, loaders, and input shapes
  - `build_model()` for model architectures and compile settings

### 🌱 Multi-Seed Experiments

`run_seeds.sh` runs a full server + client experiment for every combination of seeds, alphas, datasets, and client-selection policies sequentially. For each combination it:

1. Restarts Ganache and resets ETH balances
2. Redeploys contracts (`truffle migrate --reset`) to reset blockchain state
3. Starts the server in the background
4. Launches all clients via `launch_clients.py` and waits for completion
5. Waits for the server to finish cleanly before moving to the next combination

Prerequisites:

- `conda` environment `blockfed` must exist (the script activates it automatically)
- `ganache` and `truffle` must be installed and available in `PATH`

```bash
# Run with defaults — iterates all combinations of:
#   DATASETS=(fmnist cifar10) × ALPHAS=(0.1 0.4 0.7) × SEEDS=(42)
#   × CLIENT_SELECTIONS=(clp_aware cfl)  →  12 runs total
./run_seeds.sh

# Override any parameter via environment variables
NUM_CLIENTS=20 NUM_ROUNDS=100 BUDGET=5000 ./run_seeds.sh
```

Configurable environment variables:

| Variable | Default | Description |
|---|---|---|
| `NUM_CLIENTS` | `10` | Number of clients to launch per run |
| `NUM_ROUNDS` | `100` | FL training rounds |
| `BUDGET` | `5000` | Total reward pool (ETH) |
| `THRESHOLD` | `0.05` | CLP detection threshold |
| `CLP` | `10` | First non-CLP round for client-sampling policy |
| `MODEL_TYPE` | `cnn` | Model architecture: `cnn` or `alexnet` |
| `RATIO` | `1.4` | Geometric growth ratio for per-client sample counts |
| `BATCH_SIZE` | `32` | Local batch size |
| `LOCAL_EPOCHS` | `2` | Local epochs per round |
| `SERVER_ADDRESS` | `127.0.0.1:8080` | Flower server gRPC address |
| `CLIENT_LAUNCH_DELAY` | `0.2` | Seconds between launching each client process |
| `SERVER_STARTUP_WAIT` | `8` | Seconds to wait after server start before launching clients |
| `GANACHE_STARTUP_WAIT` | `5` | Seconds to wait for Ganache to be ready after each restart |
| `GANACHE_PORT` | `8545` | Port for the Ganache RPC endpoint |


Server logs for each run are written to `report/temp/server_<dataset>_<model>_seed<N>_<N>clients_<selection>_alpha<alpha>_<timestamp>.log`.

## 🧠 Critical Learning Period Detection
### 📉 Per-client training loss (CLP loss)

After local training each round, each client computes:

```
clp_loss_i = lr × ‖∇L(batch)‖²
```

This is the learning rate multiplied by the squared L2 norm of the gradient with respect to a single batch, computed via `tf.GradientTape` immediately after `model.fit()`.

### 📈 Federated Gradient Norm (FGN)

The server aggregates client CLP losses into a weighted average each round:

```
fgn(t) = Σ_i  (n_i / N)  ×  clp_loss_i
```

where `n_i` is the number of training samples for client `i` and `N` is the total across all participating clients that round.

### ✅ Detection rule

A round `t` is flagged as a CLP if:

```
rel_change(t) = ( fgn(t) − fgn(t−1) ) / fgn(t−1)  ≥  threshold
```

`rel_change` is undefined at round 1 (no previous FGN), so round 1 is never flagged as a CLP.

### 🧾 Console output per round

Every round the server prints a line showing all CLP values:

```
[CLP] round=2  fgn=0.004105  prev_fgn=0.003421  rel_change=+0.199942  threshold=0.05  is_CLP=True  *** CLP DETECTED ***
[CLP] round=3  fgn=0.003890  prev_fgn=0.004105  rel_change=-0.052375  threshold=0.05  is_CLP=False
```

### 💾 Saved values

`report/temp/cfl_acc_loss_<dataset>_seed<seed>.json` contains per-round keys plus final full-test metrics:

| Key | Contents |
|---|---|
| `fgn` | Weighted average gradient norm — `fgn(t)` |
| `fgn_relative_change` | `( fgn(t) − fgn(t−1) ) / fgn(t−1)` — `null` for round 1 |
| `aggregated_loss` | Weighted average training loss across clients |
| `aggregated_accuracy` | Weighted average accuracy across clients |
| `final_test_loss` | Loss of the final global model on the full held-out test set (single run-level value) |
| `final_test_accuracy` | Accuracy of the final global model on the full held-out test set (single run-level value) |
| `final_test_num_samples` | Number of test samples used for the final global-model evaluation |

## ⛓️ Blockchain Overhead Metrics

This section tracks blockchain transaction overhead for:

- Client: `addWeight`
- Server: `addStrategy`, `addModel`, `addContribution`, `paymentTransfer`

Key points:

- Only metadata is on-chain (filepath + SHA-256 hash + contract fields).
- Raw model weights stay off-chain (Flower gRPC + local `.npy` files).
- Main reported metrics are latency, gas, and throughput per function and overall.

Recommended throughput metric:

- Use `throughput_tps_processing` as the primary blockchain throughput metric.
- Use `throughput_tps` (wall-clock) only as a utilization indicator over the full experiment window.

## 📡 Latency and Communication Metrics

Each run logs training and blockchain overhead separately.

Core events:

- Training: `server.round`, `client.fit`
- Blockchain: `addStrategy`, `addWeight`, `addModel`, `addContribution`, `paymentTransfer`, `hash_computation`

Important interpretation:

- `training.fit.total_latency_s` is summed client compute (can exceed wall-clock due to parallelism).
- `training.round.total_latency_s` approximates end-to-end FL training time on server.
- `observation_span_s` is full experiment span (training + blockchain setup/teardown).


## 📁 Output Files

All outputs are grouped in:

```text
report/temp/<dataset>_<model>_seed<seed>_<N>clients_<selection>_alpha<alpha>_<timestamp>/
```

Most useful files:

- `cfl_acc_loss_*.json`: per-round aggregated loss/accuracy/FGN + final test metrics.
- `fgn_log_session*.jsonl`: incremental per-round CLP/FGN logs.
- `cfl_contribution_profile_*.json`: per-client contribution profile.
- `data_split_*.csv`: class/sample split summary.
- `blockchain_metrics_*.json`: blockchain latency/gas/TPS metrics (server, clients, overall).
- `latency_comm_*.jsonl` and `latency_comm_*_summary.json`: training + blockchain latency/comm logs.
- `client_logs/client_<id>_<timestamp>.log`: per-client runtime logs.

Saved weights:

- `Server/model_weights/<session_dir>/round-<n>-weights.npy`
- `Server/model_weights/<session_dir>/Global_model_seed<seed>.npy`
- `Client/Local-weights/Client-<id>/<session_dir>/Round-<n>-training-weights.npy`
- `Client/Global-weights/<session_dir>/Round-<n>-Global-weights.npy`
